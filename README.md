# Автообновляемый M3U-плейлист в облаке

Плейлист собирается и обновляется **сам, без вашего компьютера**. Сборку выполняют
серверы GitHub по расписанию: каждые 30 минут они скачивают ваши источники, чистят
их от дублей и мусора и коммитят готовый `playlist.m3u` в репозиторий. В плеер вы
вставляете одну постоянную ссылку.

```
GitHub Actions (cron каждые 30 минут)
   → build_playlist.py: скачал 5 источников → почистил → убрал дубли
   → записал playlist.m3u → закоммитил (только если список реально изменился)
   → ваш плеер читает постоянную ссылку
```

Текущий результат на этих источниках: **14 378 каналов**, файл 2.7 МБ, сборка ~5 секунд.

## Три плейлиста на выбор

Бот собирает сразу три файла. Возьмите тот, который подходит вашему телевизору.

| Файл | Каналов | Для чего |
|---|---|---|
| `playlist-tv-verified.m3u` | **668** | **Рекомендую для телевизора.** Каналы проверены на живость вручную — мёртвых почти нет. Обновляется в облаке, но состав фиксирован белым списком |
| `playlist-tv.m3u` | ~470 | Короткий список: только русскоязычные каналы, по 60 на группу, без тестовых подборок. Состав подстраивается автоматически |
| `playlist.m3u` | ~14 400 | Полный список всех источников. Для мощного плеера на компьютере или приставке |

Ссылка для телевизора:

```
https://raw.githubusercontent.com/ВАШ_ЛОГИН/ВАШ_РЕПО/blob/main/playlist-tv-verified.m3u
```

### Почему проверенный список лучше для ТВ

Замер на ваших источниках из российского IP: из 1364 русскоязычных каналов **живых 666**, то есть примерно половина. В коротком списке из 60 каналов на группу доля живых была всего 49% — половина каналов не открывалась.

Поэтому `playlist-tv-verified.m3u` собран иначе: я прогнал сплошную проверку живости и зафиксировал имена выживших каналов в белом списке (`include_names` в `config-tv-verified.json`). В нём Первый канал, Россия 1, НТВ, Карусель, Матч!, Eurosport, Amedia, RT Д, Беларусь 24 и региональные каналы.

Состав со временем устаревает: каналы умирают и появляются новые. Чтобы обновить белый список, запустите проверку:

```bash
python build_playlist.py            # с M3U_CONFIG=config-tv-check.json
```

Конфиг `config-tv-check.json` включает проверку живости и печатает готовый список имён между маркерами `INCLUDE_NAMES_JSON`. **Запускать только из России**: с зарубежного сервера все российские каналы будут помечены мёртвыми.

Три файла конфигурации:

- `config.json` — полный список
- `config-tv.json` — короткий телевизионный
- `config-tv-verified.json` — проверенный белый список
- `config-tv-check.json` — служебный, для обновления белого списка

## Установка: 6 шагов

### Шаг 1. Создайте репозиторий

Откройте [github.com/new](https://github.com/new), задайте имя (например `my-iptv`),
выберите **Public** и нажмите *Create repository*.

Публичный — потому что в публичных репозиториях GitHub Actions бесплатны без лимитов.
Приватный тоже сработает, но там включён лимит 2000 минут в месяц (этой сборке хватит
с большим запасом — она занимает секунды).

### Шаг 2. Загрузите файлы

На странице пустого репозитория нажмите **uploading an existing file** и перетащите
**всё содержимое этой папки**: `build_playlist.py`, `check_playlist.py`, `config.json`,
`requirements.txt`, `README.md` и папку `.github`.

> **Самая частая ошибка.** Папка `.github` должна лежать **в корне репозитория**.
> GitHub ищет расписание только по пути `.github/workflows/`. Если залить её внутри
> другой папки, например `m3u-auto/.github/...`, вкладка Actions останется пустой
> и ничего не запустится. Проверьте себя: на главной странице репозитория должна
> быть видна папка `.github`.

Если перетаскивание папки `.github` не сработало (проводник Windows иногда её не
показывает как папку), создайте файл вручную: *Add file → Create new file*, в поле
имени введите `.github/workflows/build.yml` — слэши создадут папки автоматически,
и вставьте туда содержимое файла.

### Шаг 3. Разрешите боту запись

**Settings → Actions → General → внизу Workflow permissions → Read and write
permissions → Save.**

Без этого шага сборка будет проходить, но файл не закоммитится, и в логе появится
`Permission denied`. Это вторая по частоте причина «ничего не работает».

### Шаг 4. Запустите вручную для проверки

Вкладка **Actions** → в списке слева `build-playlist` → кнопка **Run workflow** →
зелёная кнопка *Run workflow*. Через 10–20 секунд обновите страницу.

Что должно быть: галочка у запуска, а в репозитории появились два новых файла —
`playlist.m3u` и `status.txt`. Если вместо галочки красный крест — откройте запуск и
посмотрите последний шаг, там будет причина.

### Шаг 5. Возьмите ссылку для плеера

Для телевизора берите проверенный список (почему — в таблице выше):

```
https://raw.githubusercontent.com/ВАШ_ЛОГИН/ИМЯ_РЕПОЗИТОРИЯ/main/playlist-tv-verified.m3u
```

Полный список доступен по адресу с `playlist.m3u` в конце.

Именно такой вид, без `/refs/heads/`. Подставьте свои логин и имя репозитория.
Проверьте ссылку в браузере — должен начаться текст `#EXTM3U`.

Этот адрес и вставляйте в плеер. Он не меняется никогда, обновляется только содержимое.

### Шаг 6. Всё

Больше ничего делать не нужно. Расписание `*/30 * * * *` в `build.yml` запускает
сборку каждые 30 минут. Если список каналов не изменился — коммита не будет, и
репозиторий не растёт.

## Что важно знать про обновление

Плейер перечитывает плейлист, когда вы его открываете или перезапускаете. Сам он
по расписанию не обновляется — это ограничение плеера, а не вашей схемы.

## Проверка состояния

Файл `status.txt` в репозитории переписывается при каждом запуске и показывает, что
произошло: отметку времени, число каналов и построчный результат по каждому источнику —
`ok` со количеством каналов или `FAIL` с текстом ошибки.

Откройте `status.txt` на GitHub — сразу видно, какие источники живы, а какие отвалились.

Оставшиеся 5 источников отдают данные стабильно. Нерабочий источник **не ломает
сборку**: скрипт запишет его в `status.txt`, возьмёт остальные и продолжит. Поэтому
если завтра отвалится ещё один — плейлист просто обновится из живых.

## Проверка живости каналов: главная ловушка

`only_alive: true` в `config.json` заставляет проверять каждый поток отдельно.
**Не включайте её на GitHub-раннере.** Раннеры находятся в США, и все каналы с
гео-ограничением по РФ будут помечены мёртвыми — вы потеряете большую часть
российского телевидения. Замер на выборке из России: живых 68%.

Если фильтрация нужна — запускайте сборку на своём сервере в РФ:

```bash
M3U_OUT=/var/www/playlist.m3u python build_playlist.py
```

Либо проверяйте только начало списка, оставив остальное как есть:

```json
"only_alive": true,
"alive_check_limit": 500
```

## Диагностика плейлиста на своём компьютере

```bash
pip install -r requirements.txt
python check_playlist.py playlist.m3u              # группы, хосты, доля живых
python check_playlist.py playlist.m3u --limit 500  # быстрая проверка выборки
```

Показывает группы и хосты — сразу видно источники-пустышки, где тысяча каналов
сидит на одном IP. Работает даже без `aiohttp`, через пул потоков.

## Настройки `config.json`

| Параметр | Что делает |
|---|---|
| `sources` | список ссылок на источники; можно добавлять и удалять |
| `source_groups` | группа по умолчанию для каждого источника по порядку |
| `drop_junk_urls` | выбрасывать `127.0.0.1`, `localhost`, приватные адреса (нашлось 324) |
| `min_channels` | защита: если каналов стало меньше — рабочий плейлист не перезапишется |
| `include_groups` / `exclude_groups` | белый и чёрный списки групп |
| `include_name_regex` / `exclude_name_regex` | фильтр по названию канала |
| `order_groups` | порядок групп в плейлисте, остальные уйдут в конец |
| `url_base` | подменить хост ссылок на свой прокси/домен; оставьте пустым, если не нужно |

После правки `config.json` сборка запустится автоматически — в `build.yml` для этого
есть триггер `push`.

## Частота обновления

Строка `cron: "*/30 * * * *"` в `.github/workflows/build.yml`. Минимум для GitHub
Actions — 5 минут (`*/5 * * * *`), но расписание неточное: при высокой нагрузке запуск
может опоздать на 5–20 минут. Формат: минуты / часы / день / месяц / день недели,
**время в UTC** (МСК = UTC+3).

## Грабли, о которые спотыкаются все

- **Токены и пароли в `config.json` класть нельзя** — файл уезжает в публичный
  репозиторий. Секреты храните в Settings → Secrets and variables → Actions.
- Источники часто отдают `403` без заголовка `User-Agent` — в скрипте он подставлен.
- Проверка по `HEAD` врёт: часть серверов на него не отвечает. Скрипт автоматически
  повторяет запрос через `GET` с заголовком `Range`.
- `raw.githubusercontent.com` кэшируется примерно на 5 минут. Для плеера это неважно:
  он перечитывает плейлист при каждом запуске.
- Многие публичные плейлисты содержат контент без прав на распространение.
  Ответственность за выбор источников — на том, кто их подключает.
